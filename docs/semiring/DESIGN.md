## 0. 工具鏈與驗收標準

- MoonBit `moon 0.1.20261021` / `moonc v0.10.17`（2026-10-21 的 stable）。
- 驗收標準（四條，缺一不可）：
  1. **定律可執行**：每個代數實例都要通過機器檢查的定律清單；檢查器另以「故意做壞的實例」反證（negative control）。
  2. **雙實作對照**：任何被稱為「更快」的演算法，都必須與一個獨立實作／暴力法逐元素比對。
  3. **運算量可數**：⊕/⊗ 的呼叫次數由 `Ops` 累計，直接反映這次執行真正發生的基本運算。
  4. **記憶體可量**：演算法把每次元素存取回報給 `Tracer`，由 L1/L2 兩層 LRU 模擬器換算 miss 與 DRAM 用量；
     量到的是**這支程式實際發出的序列**，不是另外假設的模型。
  5. **宣稱可證偽**：任何「精確」「等價」「兩者相同」的宣稱，都必須有一條**獨立的檢查路徑**，
     而且報告要印出檢查的覆蓋率（幾格不同、幾個反例），不是「測試通過」四個字。
- 所有輸入由固定種子的 SplitMix64 產生 ⇒ 正確性結論可重現；時間取重複執行的最小值。
- 規模：15 個程式庫、native 158 / 其餘 154 個測試、四個後端全綠且 **`moon check` 0 警告**；
  `REPORT.md` 共 19 節（§19 是「誠實的限制」，逐條把邊界量成數字），全部由 `moon run cmd/semiringreport --target native` 現場輸出。

## 1. 結構的嵌套關係

```
                        ┌──────────── 完全正則 (GroupElement) ────────────┐
                        │  a° 存在 ⇒ star 可用 O(log m) 倍增計算           │
                        └───────────────▲─────────────────────────────────┘
                                        │ 提供 star
  冪等半環 ──► 自然序 ──► 格序半環 ──► 星閉半環 ──► 矩陣閉包 ──► 圖最短路
  (Idempotent)            (Ordered)     (Star)      Mat[StarSemiring]   (CSR)
       │                                                  │
       │ 原地迭代合法                                      │ 位元平行（布林半環）
       ▼                                                  ▼
  Kleene/Warshall                                    Θ(n³/64)

  么半群 (Monoid) ──► 冪等么半群 ──► sparse table（O(1) 查詢）
                  ├──► 群（有逆） ──► Fenwick（區間 = 前綴差）
                  ├──► 仿射么半群 ──► 樣條的一階遞推
                  └──► 反么半群 ──► 讓「合成順序」與「資料流方向」一致
```

三個「跨結構」的關鍵接縫：

1. **冪等 → 演算法**：冪等性使原地更新安全（§2.1），也使重疊區間合併安全（sparse table）。
2. **完全正則 → 演算法**：有限子群 ⇒ star 只需 O(log m) 次乘法（§3.2）；在圖上就是「環 + 尾巴」的 O(n) 分解。
3. **么半群 → 樣條**：樣條的求逆是兩個一階線性遞推，每一步都是仿射么半群元素 ⇒ 可用前綴掃描（§6）。

## 2. 半環：型別即前提

### 2.1 定理 A（原地 Kleene 迭代的合法性）

Floyd–Warshall 的原地更新

```
d[i][j] ← d[i][j] ⊕ d[i][k] ⊗ d[k][j]
```

對**所有**半環都正確 ⟺ 半環冪等（Aho–Hopcroft–Ullman；Backhouse–Carré 的形式化）。

- 充分性：冪等 ⇒ `d[i][j]` 已被走過的路徑再走一次不會改變值。
- 必要性：取 `S = (ℕ, +, ×)`、邊 0→1、1→2、0→2。路徑數 0→2 應為 2；
  原地 Warshall 在 k=1 時把 `d[0][1]·d[1][2]` 併入 `d[0][2]`，之後 k=2 再用更新後的 `d[0][2]`
  造出額外的乘積 ⇒ 得 2 以上。本庫在 `REPORT.md` §4b 實測：n=8 的 DAG 上暴力列舉 = 3、Lehmann = 3、硬塞原地 = **60**。

**實作決策**：`closure_fw_inplace` 的型別參數要求 `IdempotentSemiring`。
非冪等半環（計數、機率）在編譯期無法呼叫它 ⇒ 錯誤不可能「剛好在測試裡沒被踩到」。

### 2.2 定理 A'（為什麼「每輪快照」不夠）

常見的修補是「先把第 k 列/行快照再更新」，即

```
d^k[i][j] = d^{k-1}[i][j] ⊕ d^{k-1}[i][k] ⊗ d^{k-1}[k][j]
```

這在半環上仍然只是 `(I ⊕ M)^k` 的展開，**漏掉了「在 k 上打轉任意次」的因子** `d[k][k]*`。
正確的一般化是 Lehmann 的消去法。

### 2.3 演算法：Lehmann 消去（任意封閉半環）

每一輪消去頂點 k：

```
1. d[k][k] ← d[k][k]*                 (star，補上在 k 上任意次打轉)
2. d[i][k] ← d[i][k] ⊗ d[k][k]        (i ≠ k)
3. d[k][j] ← d[k][k] ⊗ d[k][j]        (j ≠ k)
4. d[i][j] ← d[i][j] ⊕ d[i][k] ⊗ d[k][j]
```

時間 Θ(n³)、額外記憶體 O(1)。與原地 Warshall 的差別**只有第 1 步**；
冪等半環中 `d[k][k]*` 可以被 `1 ⊕ d[k][k]` 取代（因為 `x* = 1 ⊕ x`），這正是兩者在冪等時重合的原因。

`closure_lehmann` 的約束是 `StarSemiring`（不需要冪等）。

### 2.4 熱帶半環的單調性剪枝

在 `(ℝ ∪ {∞}, min, +)` 中，若所有元素 ≥ 0（即 ≥ ⊗ 單位元），則

```
a[i][k] + b[k][j] ≥ a[i][k]
```

於是：

- `a[i][k] = ∞` ⇒ 整個 k 列可以跳過（省 m 次 ⊗）；
- `c[i][j] ≤ a[i][k]` ⇒ 該 (i,j) 不需要更新（省一次 ⊗ 與一次寫入）。

兩者都不改變結果。實測（n=384，密度 60%）：⊗ 次數 56.6M → 20.2M（2.8× 少），時間 5.12×。

### 2.5 閉包的三種實作與它們的差異

| 實作 | 前提 | 時間 | 空間 | 何時用 |
|---|---|---|---|---|
| `closure_fw_inplace` | 冪等 | Θ(n³) | O(1) 額外 | 熱帶、布林、瓶頸 |
| `closure_lehmann` | 星閉 | Θ(n³) | O(1) 額外 | 計數、機率、Pareto |
| `closure_blocked` | 冪等 | Θ(n³) 運算、工作集 O(n²/4) | O(n²) 遞迴緩衝 | 想要好的快取行為 |
| `closure_series` | 收斂（譜半徑 < 1） | O(k·n³) | O(n²) | 非封閉半環的近似，附收斂判據 |

## 3. 完全正則半環

### 3.1 定義與例子

a ∈ S 為完全正則，若存在 a° 使

```
a ⊗ a° ⊗ a = a,        a ⊗ a° = a° ⊗ a = e_a,        e_a ⊗ e_a = e_a
```

例子：`ℤ_m` 的冪集半環（`CyclicSet`：⊕ = ∪、⊗ = 循環和），每個支撐集都落在有限群中；
`Trop` 的乘法部分 `(ℝ, +)` 是群，但階無窮（`order_bound = 0`，走 `StarSemiring` 的解析解）。

### 3.2 定理 B（star 的對數計算）

若 a 落在階為 m 的子群中，則 `a^m = e_a`，於是

```
a* = 1 ⊕ a ⊕ … ⊕ a^{m-1}     且對任何 m 的倍數 M：a* = ⊕_{k<M} a^k
```

以倍增法計算 `⊕_{k<n} a^k`：

```
acc = 0, ap = 1, blk = 1, pb = a
for bit of n (由低位到高位):
    if bit: acc = acc ⊕ ap⊗blk ; ap = ap⊗pb
    blk = blk ⊕ pb⊗blk ; pb = pb⊗pb
```

只需 O(log n) 次 ⊗ 與 ⊕。測試對照 `star_by_iteration`（O(m)）與暴力閉包，三者一致。

**接縫**：矩陣的 star（閉包）是 `Mat[StarSemiring]`，而 `CyclicSet` 提供 O(log m) 的 star，
所以「完全正則」直接變成矩陣閉包的加速器，而不是另一個孤立的玩具。

### 3.3 圖論面的等價物：功能圖

出度 ≤ 1 的圖，每個點最終進入一個環（有限週期子群）。於是

- 閉包結構 = 「尾巴 + 環」，可 O(n) 求出（`functional_decompose`）；
- 可達點數 = 環長 + 到環的距離，O(1) 查詢。

位元平行 Warshall 需要 O(n³/64) 字運算與 O(n²/64) 記憶體；分解只需 O(n)。
測試在 n=600 上逐點比對兩者。

## 4. 格序半環

### 4.1 定義

`OrderedSemiring`：冪等半環 + 格結構，`join = ⊕`、另有 `meet`，且 ⊗ 對 join/meet 皆分配。
實例：布林、瓶頸 `(max, min)`、Pareto 集合。

### 4.2 ParetoSet：多目標最短路

標籤集合 ⊕ = 聯集 + 支配剪枝（吸收律 `x ⊕ (x ⊕ y) = x ⊕ y`）、⊗ = 閔可夫斯基和 + 剪枝。

- 剪枝是 canonical form：保留的標籤按字典序排序 ⇒ 同一個集合有唯一表示 ⇒ 交換律在值層面嚴格成立
  （若不排序，`a ⊕ b` 與 `b ⊕ a` 只是同一個集合的不同排列，等值判定就會失敗）。
- 單位元 `1` 需要承載維度，用 `dim = -1` 作哨兵；`⊗` 遇到哨兵直接回傳另一邊。
- 剪枝的意義：沒有它，標籤數隨簡單路徑數成長；有了它，實測每位點 3.6–5.4 個標籤。

正確性由 DFS 列舉全部簡單路徑的暴力法逐點比對（測試）。

### 4.3 瓶頸半環

`(max, min)`：⊕ = max、⊗ = min、零元 = 0（不連通）、單位元 = ∞（無限容量）。
`widest_path` 用同一套 label-setting 骨架（最小堆存 −capacity），與瓶頸閉包逐點比對。

## 5. 複雜度的四個層級（以全源最短路為例）

| 層級 | 演算法 | 時間 | 前提 | 實測 n=320, m=3103 |
|---|---|---|---|---|
| 1 | Kleene 閉包（矩陣） | Θ(n³) | 封閉半環 | 4.38e5 µs |
| 2 | n × Dijkstra（`csr_apsp`） | Θ(n·m log n) | 選擇性 + 非負權 | 1.33e5 µs |
| 3 | 位元平行 Warshall | Θ(n³/64) | 布林 | 1.01e3 µs |

這張表就是「結構知識換複雜度」的具體形式：每一層都犧牲一般性換取速度，而犧牲的一般性在型別上寫得出來。

## 6. 樣條空間

### 6.1 配點矩陣是帶狀的

均勻三次 B 樣條在整數節點上求值：`A` 為循環三對角 `(z⁻¹ + 4 + z)/6`。
帶狀 LU 是 O(n·p²)，稠密高斯消去是 O(n³)；兩者以 `interp_cubic_dense_open` / `interp_cubic_banded` 對照。

### 6.2 極點分解（Unser–Aldroubi–Eden 1993）

```
z⁻¹ + 4 + z = (−1/ζ)(1 − ζz⁻¹)(1 − ζz),       ζ = −2 + √3 ≈ −0.2679
```

求逆因此等於解兩個一階遞推：

```
forward :  u_i = (−6ζ)·y_i + ζ·u_{i−1}
backward:  c_i = u_i + ζ·c_{i+1}
```

邊界以幾何級數**精確**初始化（|ζ| < 1 ⇒ 收斂極快）。這裡踩過的坑：
`c_{i} = u_i + ζ c_{i+1}` 展開是 **往前** 的級數 `Σ_k ζ^k u_{i+k}`，不是往後；
初值方向錯了會得到 0.2 量級的殘差，但程式仍然「跑得動」——只有殘差檢查抓得到。

**接縫**：每個遞推步 `x ↦ ζx + y_i` 是仿射么半群 `AffineM` 的元素，整條遞推是么半群前綴掃描。
掃描方向與資料流相反，因此用 `OppositeM` 包一層，讓 `prefix_scan` 的語義對齊（§7.3）。

### 6.3 數值結果

殘差 `max_i |(c_{i−1} + 4c_i + c_{i+1})/6 − y_i| ≈ 7e−16`（n 到 1024），
遞迴解相對稠密解在 n=1024 時快 4251×。

## 7. 么半群與聚合

### 7.1 三種代數強度對應三種結構

| 結構 | 代數要求 | 建表 | 查詢 | 為什麼 |
|---|---|---|---|---|
| `SegTree` | 么半群 | O(n) | O(log n) | 只需要結合律與單位元 |
| `SparseTable` | **冪等**么半群 | O(n log n) | O(1) | 查詢用兩個重疊區間，重疊部分被算兩次 |
| `Fenwick` | **群**（有逆元） | O(n) | O(log n) | 區間 = 前綴差，需要逆元 |

把要求的代數強度寫成型別約束，就同時得到「正確性前提」與「可替換性」：
`MaxI64` 不能塞進 Fenwick（沒有逆元），`SumI64` 不能塞進 sparse table（不冪等）。

### 7.2 前綴掃描：深度 vs 工作量

Hillis–Steele 原地掃描：工作量 O(n log n)、額外空間 O(1)、**深度 O(log n)**。
序列累加：工作量 O(n)、深度 O(n)。實測 n=65536 時掃描慢 17.7×（≈ log₂ n），
但它的深度是 log n——在管線化/平行後端上這是延遲的來源。
兩者都實作，讓這個取捨可以被量測而不是被宣稱。

### 7.3 反么半群

`OppositeM[M]` 只把 `combine` 的順序顛倒。它不是「新資料結構」，而是讓
「函數合成」這個么半群的乘法方向與資料流方向一致的工具；
有了它，樣條的遞推掃描不需要客製化任何掃描程式碼。

## 8. 限流：兩個攻擊面

### 8.1 GCRA 的不變量

狀態是每個鍵的 `TAT`（理論到達時間，Int64 微秒）。判定：

```
allowed  ⟺  now ≥ TAT − τ + backoff(strikes),      τ = (burst − 1)·interval
commit   :  TAT ← max(now, TAT) + interval
```

不變量（測試逐條驗證）：

1. 任意 2 秒視窗內放行量 ≤ burst + rate·2（單點狂按的上限）。
2. 連續被拒會使 `backoff` 指數成長（上限 64×interval）⇒ 越打越便宜。
3. 時間倒退（NTP 回撥）被夾在 `last_now`，不會把 TAT 推到未來造成長期誤鎖。

### 8.2 有界鍵表

開放定址 + CLOCK 近似 LRU，容量固定。逐出是 O(1) 攤還；
這個結構是「用無限多個 key 打爆記憶體」這條攻擊面的直接對策。

### 8.3 多點齊發：全域閘門在雜湊之前

判定順序：全域閘門（一次 Int64 比較）→ 租戶（一次雜湊）→ 鍵（一次雜湊）。
5 萬個不同鍵在同一微秒抵達時，只有 100 個進入雜湊，其餘 49,900 個在第 1 步就被丟棄（約 0.7 ms 處理完 5 萬次決策）。

### 8.4 preview / commit 兩段式

階層限流若「先扣租戶額度再看鍵」，被鍵層拒絕的請求會白白消耗租戶預算
（phantom consumption）。本庫讓三層都先 `preview`（只讀狀態），全部通過才一起 `commit`，
因此不需要 rollback。測試斷言：200 次鍵層被拒之後，租戶額度仍有 49（= burst 50 − 1 次成功）。

## 9. 量測方法

1. **時間**：`time_min(reps, f)` 取重複執行的最小值（最小值比平均值更接近無干擾成本）。
2. **運算量**：`Ops` 計數器掛在每次 ⊕/⊗ 上，量測時用**單次執行**的獨立計數器（避免重複執行累加）。
3. **記憶體**：`Tracer` 給每個矩陣一段互不重疊的虛擬位址空間，演算法的每次元素存取被送進
   L1(32 KiB, 8-way, 64 B)/L2(512 KiB, 8-way, 64 B) 的 LRU 模擬器；DRAM 用量 = L2 miss × 8 words。
   模擬器本身也有測試（循序、strided、工作集）以確保數字有意義。
4. **可重現**：所有輸入由固定種子 PRNG 產生；報告中的「一致」欄位是本次執行真的比對出來的。
5. **負面結果**：分塊在 n=256/384 的 wall clock 上沒有優勢（0.91–1.19×），但把 n=256 的 L1 miss 從 1.06M 降到 0.56M（n=192 時分塊再降 15×）。
   兩件事都寫進報告——泛型內核在此工作集下是 compute-bound，這是「何時該做資料佈局優化」的判據。

## 10. 稀疏路徑（CSR）：什麼時候值得離開稠密

### 10.1 三個不同的「稀疏」問題

稀疏不是一種資料結構，而是三個不同的問題：

1. **儲存**：只存非零 ⇒ 記憶體 O(nnz)，但每次 `get` 變成二分搜尋。
2. **運算量**：只有真正非零的 (i,k,j) 才做 ⊕/⊗ ⇒ SpGEMM 的 Θ(Σ_{(i,k)∈a} nnz(b_k))。
3. **演算法選擇**：稀疏圖的最佳演算法往往不是「稀疏版的稠密演算法」，而是完全不同的演算法
   （單源 Dijkstra 取代 Floyd–Warshall）。

本庫三件事都做，並且分別量測（報告 §10a–10c）。

### 10.2 SpGEMM：SPA 累加器

Gustavson 式稀疏乘法對 a 的每一列 i，把 `a[i][k] ⊗ b[k][j]` 併入一個「稀疏累加器」：

```
acc : 稠密陣列（長度 = b.cols）
mark : 時間戳，mark[j] == i 表示「本列碰過 j」
touched : 本列真正碰到的欄（最後排序輸出）
```

時間戳是關鍵：它讓「清空累加器」從 O(n) 變成 O(1)，因此每列的額外成本只有真正出現的欄。
輸出必須維持欄索引遞增（canonical form），否則下一次二分搜尋會失效——排序成本被記在 `touched` 上，
而不是整列。

實測（n=128、degree=4）：⊗ 次數與稠密剪枝版完全相同（5934），時間 268 vs 477 µs。
**差距全部來自記憶體**：稠密版掃過 16384 個格子，CSR 版只碰 nnz(a) 條邊。

### 10.3 稀疏 Kleene 消去，與它為什麼輸

對 k = 0…n−1：把第 k 列載入稠密暫存（含 `star(d[k][k])` 的處理），
再對所有「有邊射向 k」的 i 做 `row_i ⊕= (row_i[k] ⊗ star) ⊗ row_k`。
工作量是 Θ(Σ_k indeg(k) · (|row_i| + |row_k|))，比稠密 FW 的 Θ(n³) 小得多。

但**實測它更慢**（報告 §10a/§10b）：

- 隨機圖的閉包幾乎是滿的（n=96、degree=3 → nnz = 8648 ≈ n²）：稀疏的優勢前提不成立；
- 二元樹的閉包確實只有 Θ(n log n)（n=512 → 4107 個非零），但每次列合併都要**配置並重建列陣列**，
  常數把 Θ() 的優勢吃光，仍慢 3.6×。

結論寫進報告：稀疏的判據是**閉包的 nnz**；而在稀疏輸入上真正該用的是 `csr_sssp`（n 次堆最佳化單源），
它在樹上 n=512 時快 3.2×。要讓稀疏消去翻身需要「預留容量的打包列 + 免配置合併」，
那是工程優化，本庫不宣稱未量測的收益。

### 10.4 交叉點表（實測）

| 情境 | 贏家 | 倍率 |
|---|---|---|
| 稠密閉包（隨機圖） | 稠密 FW | 稀疏消去慢 5–7× |
| 稀疏閉包（樹） | `csr_apsp` | 3.2× 快於稠密 FW |
| 稀疏 × 稀疏 | CSR SpGEMM | 1.78× |
| 只需可達性 | 位元並行閉包 | 435×（n=320：1.01 ms vs 438 ms） |

## 11. 浮點熱帶半環：只在 ULP 內封閉

### 11.1 問題

`(ℝ ∪ {+∞}, min, +)` 若要當半環用，⊗ = `+` 必須滿足結合律。IEEE-754 的加法**不滿足**：

```
(-10.01 + -5.69) + -14.07  ≠  -10.01 + (-5.69 + -14.07)
```

差 1 ULP。這不是實作 bug，而是浮點的事實。本庫的處理方式是**把它變成可檢驗的斷言**：

- `check_semiring`（精確等值）對 `TropF` 必須回 `false` —— 負面對照；
- `check_semiring_approx`（eps = 1e-9）必須回 `true`。

兩者在測試與報告 §11 都跑。任何「浮點也算半環」的宣稱都必須附帶這兩個結果，否則就是在說謊。

### 11.2 為什麼剪枝在浮點上仍然精確

剪枝只用到 `min` 與比較：

```
if is_inf(x) skip                 // 精確
if closer(cand, cur) cur = cand    // min 是精確運算
```

被改變的只有「哪一個候選先被寫進格子」，而 `min` 對順序不敏感，所以剪枝版與泛型版**逐位元相同**
（報告 §11b 的最大差 = 0）。會失準的是 `+` 的結合順序，不是 `min`。

### 11.3 NaN

NaN 與任何數比較都是 false，會讓 `min` 與 `is_inf` 都得到無意義的結果。
`TropF::of` 因此把 NaN 正規化成 `+∞`（不可達），讓壞輸入不會污染整張距離矩陣。

### 11.4 介面設計

`TropicalSemiring` 把「+∞ 哨兵」與「嚴格更近」拉進型別：

```
trait TropicalSemiring : IdempotentSemiring {
  fn inf() -> Self
  fn is_inf(Self) -> Bool
  fn closer(Self, Self) -> Bool     // cur ⊕ cand ≠ cur 的具體化
}
```

於是 `mul_trop_generic`、`csr_mul_minplus`、`csr_sssp`、`csr_closure` 都只寫一份，
`Trop`（Int32，精確）與 `TropF`（Double，ULP 內）共用同一個內核；
剪枝比較不需要把權重轉成浮點。

## 12. 分塊大小：由快取預算推導

### 12.1 兩個不同的「裝得下」

分塊有兩個獨立的容量條件，混在一起講就會選錯：

| 條件 | 對象 | 預算 | 磚數 | 公式 |
|---|---|---|---|---|
| 內層磚 | `fw_region` / 乘法內核的 b×b 區塊 | L1 | 2 | b ≤ √(fill·L1/(2·elem)) |
| 遞迴切點 | 分塊 Kleene 同時活著的子矩陣 | L2 | 3 | b ≤ √(fill·L2/(3·elem)) |

L1 = 32 KiB、elem = 4 bytes、fill = 3/4 ⇒ b = 48；L2 = 512 KiB ⇒ 176。
兩者差一個數量級，正是「用 L2 算出的 b 讓 L1 全 miss」這類錯誤設定的來源。

### 12.2 用追蹤器驗證（可否證的模型）

報告 §12b 對 n=192 掃 b ∈ {8,16,32,48,64,96,128} 的 L1 miss：

- b=48（模型選擇）的 miss 最優值（b=64）的 1.19×；
- b=8 是最優值的 3×；b ≥ n 是 12–15×。

也就是說：模型不是「剛好等於最優」，而是**落在最優的 20% 內，且遠離災難區**。
這比宣稱「我們調到了最優」誠實，也比硬寫 32 可攜。

### 12.3 為什麼不寫死 32

`closure_blocked(threshold=32)` 在 4 bytes 元素 / 32 KiB L1 上其實偏小（模型給 48），
在 8 bytes 元素（`TropF`）上又偏大（模型給 32）。門檻是一個**機器相關常數**，
讓它由 `(cache, elem, tiles)` 推導，就同時得到可攜性與可解釋性。

## 13. 平行後端：能買到什麼

### 13.0 兩個套件，一個接縫

`par/`（序列，四個 target）與 `par_host/`（native，`moonbitlang/async`）提供同一組語義；
`ShardIO` 定義在 `par/`，兩個後端都填同一種型別。呼叫端換一個 import 就換後端，
演算法、分段方式、歸約順序完全不變——這正是「接縫」的定義：**唯一與平台相關的東西是一個函式**。

### 13.1 事實

MoonBit 0.10.17 唯一的官方並行執行環境是 `moonbitlang/async`（0.22.5），
它是**單執行緒、協作式**：使用者程式碼只用一個 CPU 核心（官方 README 與部落格皆明載），
只有 I/O 工作會被丟到內部的 OS 執行緒池。真正的共享記憶體執行緒目前沒有穩定支援
（第三方 `Milky2018/pthread` 自述「Don't use it in production」，`luna_thread` 是 FFI 實驗）。

### 13.2 設計：一個接縫

```
pub fn par_for(chunks : Int32, f : (Int32) -> Unit) -> Unit    // 唯一與後端相關的 primitive
```

- native：`@async.run_async_main` + `with_task_group` + `spawn_bg`（結構化併發、取消、生命週期）；
- js / wasm / wasm-gc：序列迴圈（語義完全相同）。

所有高階演算法（`par_map_chunks`、`par_sum`、`par_scan`、`mul_rows_par`、`closure_fw_par`）
只依賴這個接縫，因此換後端不需要改任何演算法。

### 13.3 平行的正確性條件

- `mul_rows_par`：每個任務只寫自己的列區塊 ⇒ 沒有共享寫入。
- `closure_fw_par`：每一輪 k 先**快照**第 k 列/行，之後所有 i 的更新彼此獨立
  （Floyd–Warshall 的標準平行化）。快照讓結果可重現，且與序列版逐位元相同。
- `par_sum`：每段各自累加，最後**依索引順序**合併 ⇒ 浮點或非結合運算也不會因排程改變結果。
- `par_scan`：Hillis–Steele，每層的更新彼此獨立，深度 O(log n)。

### 13.4 實測

| 面向 | 結果 | 解讀 |
|---|---|---|
| CPU 密集任務（chunks 1→64） | 0.99–1.01× | 沒有加速：單執行緒跑協作式任務只是輪流 |
| 對數深度掃描 | 慢 49× | 用時間換深度；單核上是純虧 |
| I/O 重疊（12 個 shard） | 讀取 1.32× | 真的重疊了（內部 I/O 執行緒池） |
| 端到端（讀 + 解析） | 1.03× | 解析是序列 CPU，把收益攤薄 |

### 13.5 因此這個模組的價值是什麼

1. **I/O 重疊**：在 I/O 佔比高的負載（冷快取、網路檔案系統）上直接有效。
2. **結構化生命週期**：task group 保證所有子任務同步結束，不需要手寫 join。
3. **相依性被寫進程式結構**：列區塊互不相交、掃描分層，這些是真正執行緒後端的必要條件，
   而且現在就能被測試（與序列版逐位元比對）。
4. **誠實**：報告同時列出 1.32× 與 1.00×，不把 I/O 的加速誤植成 CPU 的加速。

## 14. 熱帶幾何：值域是組合多面體（`trop/`）

熱帶半環把「加」變成 min、「乘」變成加之後，多項式的**圖像**不再是一條曲線，而是 ℝⁿ 上
一條分段線性凹函數；它的**不可微點集合**才是幾何物件。這一節把三個經典結論寫成可執行程式，
每個結論都附一條獨立的檢查路徑。

### 14.1 定理 C（單變數熱帶根 = 下凸包的斜率）

對 f(x) = min_i (c_i + i·x)，令 S = {(i, c_i)} ⊂ ℤ²。把 S 取**下凸包**（lower hull，
即對每個 x 方向都最小化的那個鏈）。則：

1. 下凸包有 k 條邊，第 j 條邊的斜率 s_j ⇒ 熱帶根 r_j = −s_j；
2. 重數 mult_j = 該邊在 i 軸上的水平投影長度；
3. Σ_j mult_j = deg f = max{i : c_i < ∞}。

**為什麼**：f 在區間 [i_j, i_{j+1}] 上就是那條邊的線性函數（下包絡 = 凸包的下側），
斜率 = (c_{i+1}−c_i)/(i_{j+1}−i_j)。「兩項同時達到最小值」⇔ x 落在該邊的投影上。
根的計數則是頂點差分的望遠鏡求和。

**三條獨立檢查**（`trop/poly.mbt` + `trop_wbtest.mbt` + 報告 §14a）：

| 檢查 | 做法 | 失敗會出現什麼 |
|---|---|---|
| 重數守恆 | `multiplicity_sum() == degree()` | 根憑空消失 |
| 根處並列 | 在 r_j 上呼叫 `argmin_at()`，斷言恰好是該邊的兩端點 | 凸包與求值不一致 |
| 乘法定理 | 200 組隨機 f,g：`roots(conv(f,g)) == merge(roots f, roots g)` | 卷積或排序有錯 |

以 c = [0,10,3,7,1,9,4] 為例：下凸包為 (0,0)→(4,1)→(6,4)，得根 **−1/4（重數 4）** 與
**−3/2（重數 2）**，重數和 6 = deg f。求根耗時 1.35 µs。根用有理數 `Rat` 精確表示，
不是浮點近似——這是刻意的：熱帶幾何的陳述都是整數／有理數命題。

### 14.2 定理 D（熱帶基本定理：細分 ↔ 對偶曲線）

設 A ⊂ ℤ² 有限、c : A → ℤ。把點 (a₁, a₂, c_a) ∈ ℤ³ **抬升**，取三維下凸包的**下側面**，
投影回平面 ⇒ A 的凸包的一個**正則細分** 𝒮。其對偶圖（每個細分面 ↔ 一個頂點，
共享細分邊 ↔ 一條邊）就是熱帶曲線 V(f)。

不用任何浮點的理由：判定「點 p 在平面 π 的上方」是交叉積與點積的整數比較。
本實作的 `subdivision()` 是「枚舉三元組 → 求平面 → 全點檢查是否在其上」的 O(m⁴)
（m = 支援點數），慢但無條件正確；這正是要的：細分是其它一切的**地基**，地基不該有數值誤差。

**三個可量測的恆等式**（報告 §14b）：

1. **覆蓋**：Σ_{F∈𝒮} area₂(F) = area₂(Newton(f))。實測 6 點多項式：10 = 10。
2. **對偶性**：對每個細分面 F，以整數法向量 (n_x, n_y, n_z) 求 argmin 恰得 F 的成員集合
   ⇒ F 是法扇的一個格。實測 5/5 通過。
3. **平衡**：Σ_e w_e · ν_e = 0 對每個頂點成立，其中 w_e = 細分邊的格長、ν_e = 其外法向。
   實測最大殘差 **0**（整數恆等式，不是「接近 0」）。

另外做了一個「打平（tie）」的壓力測試：取 20 000 個隨機方向向量，統計 argmin 落在多於一個
支援點上的情況共 404 次，並斷言每一次都被某個細分面解釋掉（0 次無法解釋）。
這一項比前三項更難造假：它檢驗的是「法扇的格」是否真的**覆蓋整個平面**。

### 14.3 熱帶線性代數：det_trop = 最佳指派

    tropdet(A) = min_{σ∈S_n} Σ_i A[i][σ(i)]

這同時是**最小成本完美匹配**。於是同一件事有三個獨立實作：

| 實作 | 複雜度 | 角色 |
|---|---|---|
| `trop_det` | O(n³)（匈牙利 + 勢能） | 生產路徑 |
| `trop_det_dp` | O(n·2ⁿ)（子集 DP / 位元遮罩） | 小 n 的無條件正確對照 |
| `trop_det_bruteforce` | O(n!) | 只用來驗 n ≤ 8 |

實測（µs）：n=5 5.08 / 3.71 / 16.25；n=7 8.36 / 21.47 / 820.82；n=9 14.07 / 119.25；
n=11 25.28 / 564.88。交叉點在 n≈6：再往上匈牙利完勝，2ⁿ 與 n! 只作為**比對基準**存在。

`trop_det_tie_count` 回報「達到最小值的排列個數」，也就是熱帶奇異性的程度：
一般隨機矩陣為 1；三列相同的 3×3 矩陣得 det = 6、**tie_count = 6**（六個排列全並列）。
這個欄位是為了讓「退化的熱帶曲面」變成一個可以被斷言的數字，而不是一句形容詞。

### 14.4 這一節買到什麼、沒買到什麼

- 買到：熱帶幾何的每一句宣稱在庫裡都對應一個**整數恆等式**，可以斷言 `==`，不需要容差。
- 買到：熱帶行列式把「代數定義 → 組合演算法」的推導寫成同一份程式碼的三種實作。
- 沒買到：細分上界是 O(m⁴)，m 只到幾十；沒有增量凸包，也沒有處理高維（3 個以上變數）。
  報告 §19c 量了這件事：m = 6…14 的 log-log 斜率實測約 **2.5**（面數是離散的，單點差分会亂跳），
  所以只能宣稱上界，不能宣稱「實測吻合 O(m⁴)」。
- 沒買到：熱帶曲線的**交點理論**（stable intersection、multiplicity）不在本庫範圍。

## 15. 規範形式：把「相等」變成「字串相同」（`nf/`）

半環裡的元素有無窮多種寫法，「兩個表示式是否相等」在一般情形下不可判定。
但對本庫真正用到的兩類代數，可以給出**可判定的正規形**，而且可以給出**兩條互不相依**的判定路徑。

### 15.1 三層正規化

```
項 (Regex / SExpr)
  │ ① ACI 正規形：⊕ 攤平成排序去重集合、⊗ 用 0/1 吸收律化簡、* 用 0*=1*=1、(a*)*=a*
  ▼
有限狀態集合（Brzozowski 導數的不動點）
  │ ② Moore 分割細化 ⇒ 最小 DFA（Myhill–Nerode 唯一）
  ▼
最小 DFA
  │ ③ 依字母表固定順序、BFS 首次到達順序編號 ⇒ canonical 字串
  ▼
正規形（逐位元可比對）
```

第 ① 層不是可選的最佳化，而是第 ② 層**能夠終止**的前提：導數集合只有在 ACI 商掉之後才有限。
若把 `RSum` 留成二元樹，`d/dx (a+b)* ` 會不斷產生同構但不同結構的項，自動機永遠建不完。
這個「先商掉再建狀態」的順序，是 Brzozowski 導數法在實作上唯一的真陷阱。

第 ③ 層的關鍵是**全序**：狀態編號必須只依賴語言本身（BFS 距離 + 字母表順序），
不能依賴雜湊或插入順序，否則同一語言會有兩個正規形。

### 15.2 兩條判定路徑，必須給同一個答案

| 路徑 | 內容 | 完備性 |
|---|---|---|
| A（代數） | `SExpr` → 單項式集合的排序正規形（有限語言 = 有限冪等半環元素） | 對自由冪等半環完備 |
| B（自動機） | `SExpr` → 無星表示式 → 導數 DFA → 最小 DFA → canonical | 對正則語言完備 |

兩條路徑的**交集**（冪等半環表示式）上，它們必須一致。實測 300 組隨機表示式對，**300/300 一致**，
每次判定 0.19 µs。測試也刻意檢查「不一致」是可能的：對非冪等半環（ℕ 的加法），
`a ⊕ a = a` 不成立，而路徑 A 會誤判為相等 ⇒ 因此所有 API 名稱都帶 `idempotent`，
型別名字本身就是限制條件的宣告。

### 15.3 最小化的效果

導數 DFA → 最小 DFA 的狀態數（報告 §15）：

| 表示式 | 導數 DFA | 最小 DFA |
|---|---|---|
| `(a+b)*` | 2 | 2 |
| `(a* b*)*` | 4 | **2** |
| `(a+b)* (a+b)*` | 3 | **2** |
| `(ab)* (ab)*` | 4 | **3** |
| `((a+b)*)*` | 2 | 2 |
| `a* b*` | 3 | 3 |

縮掉的那些狀態正是「星的重複」與「和的冪等」在自動機上的影子：
`(a* b*)* = (a+b)*`、`R R = R`（當 R 含 ε 時）——代數恆等式直接反映為狀態合併。

### 15.4 邊界

- 判定的是 **Kleene 代數等式**（正則語言）與**自由冪等半環等式**（有限語言）。
- 不是所有半環的等式理論都可判定；交換半環、ℕ 半環的等式理論不在本庫能力內。
- 沒有實作 Hopcroft O(n log n) 最小化，用的是 Moore 的 O(n²·|Σ|)。
  在本庫的規模（n ≤ 數百）上 Moore 的常數更小，但這是規模假設，不是漸近優勢。
- 沒有處理帶權自動機（加權正規形是另一個問題：需要半環上的線性方程求解）。

## 16. 範疇化與解範疇化（`cat/`）

### 16.1 集合值矩陣：加 ↔ 不交併、乘 ↔ 笛卡兒積

範疇化在矩陣這一層可以寫得非常具體：

| 純量世界 | 範疇世界 | 解範疇化（基數） |
|---|---|---|
| a | 集合 A（a 的**見證**） | \|A\| = a |
| a + b | A ⊔ B | \|A\| + \|B\| |
| a · b | A × B | \|A\| · \|B\| |
| 矩陣 M[i][j] | 每格是一個集合（Hom 集合） | 逐格取基數 |

`cat/setmat.mbt` 同時保留兩層：集合值矩陣負責**列舉見證**，基數矩陣負責**算數字**。
第 16.2 節的定理要求這兩條路徑逐格相等。

### 16.2 定理 E（基數是半環同態）

若 ⊕ 在範疇層是餘積（不交併）、⊗ 是積（笛卡兒積），則 `|·|` 是從「集合半環」到 ℕ 半環的
半環同態。因此：**先在範疇層算再取基數** 與 **先取基數再在半環裡算** 必然相同。

實測（報告 §16a）：n=5 隨機圖，見證總數 67，兩條路徑逐格比對 **0/36 格不一致**，耗時 33.92 µs。
這個測試的價值在於它是**否證性**的：只要 `⊔` 或 `×` 寫錯一次（例如把笛卡兒積寫成不交併），
基數同態立刻破裂，且錯誤會出現在具體的某一格上。

### 16.3 自由範疇 = ℕ 半環上的 Kleene 星

圖 G 的自由範疇 Hom(i,j) = 從 i 到 j 的所有路徑（含長度 0）。於是

    |Hom(i,j)| = (I ⊕ A ⊕ A² ⊕ …)[i][j] = (A*)[i][j]   在 ℕ 半環上

也就是說「自由範疇存在」與「星在 ℕ 上算得出來」是同一件事。對 DAG，這個級數有限且
有四條獨立算法：

| 方法 | 做法 | 實測 n=7、31 條路徑 |
|---|---|---|
| Hom 列舉 | 直接 DFS 把每條路徑列出來 | 15.83 µs |
| 拓撲 DP | 逆拓撲序累加 | **4.39 µs** |
| 矩陣冪級數 | I ⊕ A ⊕ A² ⊕ … 逐項乘 | 81.38 µs |
| Lehmann 消去 | 原地 Kleene 消去 | 5.37 µs |

四者逐格相同。注意這是**同一個定理的四種證明策略**在效能上的分布：
列舉買到見證（可以回答「是哪 31 條」），DP 買到速度，級數買到「不解方程、純代數」的
證明（因此可用於任意封閉半環），消去買到原地記憶體。沒有哪一個是「對的」——
選哪一個取決於你要見證還是要數字。

### 16.4 Maslov 解量化：h → 0

另一條「忘掉結構」的路線不是取基數，而是**退化**。把半環元素寫成指數形式 a = e^(−A/h)：

    a ⊕ b ↦ e^(−A/h) + e^(−B/h) ──h→0──▶ e^(−min(A,B)/h) ↦ A ⊕ b
    a ⊗ b ↦ e^(−(A+B)/h)                      ↦ A ⊗ b

於是

    −h · ln( Σ_i e^(−x_i/h) ) ──h→0──▶ min_i x_i

**實作上的兩個坑**（兩者都在 `cat/dequant.mbt` 裡處理了，且報告 §16c 印出後果）：

1. **下溢**：`exp(−x/h)` 在 x/h > 709 時歸零，於是 `ln 0 = −∞`。實測 h=0.001 時樸素版就已
   給出 `∞（ln 0 下溢）`。解法是 log-sum-exp 的平移：先減去最小項，結果再加回。
2. **h 的尺度**：h 太小沒有差（落進機器精度），h 太大則「極限」還沒發生。真正的可行區間是
   `1/709 ≪ h ≪ x 的動態範圍`。實測誤差曲線：h=1 → 0.690085，h=0.1 → 0.000672，
   h=0.01 → 0（機器精度）；而樸素版在 h ≤ 0.001 崩潰。

同時驗證了矩陣層：min-plus 乘積與「解量化後的普通乘積再解量化」的最大差
h=0.1 時 5e-6、h=0.01 時 0。

### 16.5 兩種解範疇化是正交的

| | 取基數 | Maslov h→0 |
|---|---|---|
| 忘掉什麼 | 見證的多重性（集合 → 個數） | 加法的「多路徑」結構（和 → 極值） |
| 目標半環 | ℕ（或任何半環） | 熱帶 |
| 精確？ | **精確**（同態） | 只是極限（浮點上只能到誤差曲線） |
| 可否證方式 | 逐格比對兩條路徑 | 誤差隨 h 的收斂曲線 + 下溢邊界 |

它們不互相取代：一個是**代數同態**，一個是**極限**。把兩者混為一談是這一帶最常見的誤解
（例如把「熱帶化」說成「取基數的特例」）。

## 17. 代數路徑問題與演算法組合（`app/`）

### 17.1 APP 範式

給一個半環 (S, ⊕, ⊗, 0, 1) 與一個邊權矩陣 A，**代數路徑問題**就是求 A*。
定理（Lehmann / Backhouse–Carré）說：只要半環封閉，A* 可由 Kleene 消去在 O(n³) 求得。
於是「換半環 = 換演算法」不是類比，而是**同一段程式**：

| 半環 | ⊕ / ⊗ | A* 的語義 | 教科書名字 |
|---|---|---|---|
| `BoolSr` | or / and | 可達性 | Warshall、BFS |
| `Counting` | + / × | 路徑數 | DAG 上的 DP |
| `Trop` | min / + | 最短距離 | Floyd–Warshall |
| `Bottleneck` | max / min | 最寬路徑 | FW 的 max-min 版 |
| `Prob` | + / × | 路徑機率總和 | 前向–後向 |

`app/closed.mbt` 只寫一次 `app_closure`；`E` 決定它是哪一個演算法。
實測（報告 §17）：同一個函式在這五個半環上，分別與 **BFS / 拓撲 DP / 局部 FW / max-min FW /
冪級數** 逐格相同。

誠實的部分：`Counting` 與 `Prob` 在**有環**圖上級數發散 ⇒ 閉包只有在 DAG（或譜半徑 < 1）上
有意義。因此 `Prob` **故意沒有** `StarSemiring` 實例，改成 `closure_series` + `is_small` 旗標：
收斂性是可檢查的回傳值，不是假設。

### 17.2 演算法組合：N 個版本 + 仲裁

既然同一個問題有這麼多實作，就可以做一件在生產環境裡很有用的事：
**同時跑多個獨立實作，逐格比對，任何一格不一致就報警**。這不是冗余，是**交叉驗證**。

實測（n=40、119 條邊的稀疏圖，µs）：

| 實作 | 時間 |
|---|---|
| 原地 Warshall | **596.45** |
| Lehmann | 670.73 |
| 分塊 32 | 1117.77 |
| CSR APSP | 1008.39 |
| 冪級數 | 67198.21 |

五個版本逐格相同。總成本 70 591 µs，**可信度的價格 = 118.35×**。

這個數字是這一節的重點：交叉驗證**不是免費的**，而且價格由最慢的候選決定。
工程結論不是「全部跑」，而是「**上線路徑用最快的那一個，觀測路徑用最便宜的第二個**」——
本庫提供 `consensus_trop(edges, reps, inject_wrong~)` 讓這件事變成一行呼叫，以及 `cost_of_trust`
欄位讓「你付了多少」變成可量測的值。

負面對照：`inject_wrong = true` 時，人工把一個候選的某一格改壞，仲裁必須立刻失效
（實測：6 個候選、`agree = false`、**恰好 1 個**被標記）。若這條測試失敗，仲裁器就是在說謊。

### 17.3 邊界

- 仲裁只保證「這幾個實作在同一個輸入上一致」，**不保證它們都對**。共同的建模錯誤無法被發現。
  這是交叉驗證的古典限制，不是本庫能解決的。
- 冪級數候選在有環圖上需要 k 上限；`closure_series(k=2)` 的截斷就是文件化的負面對照。
- 沒有實作「候選按輸入特徵動態選擇」（那需要 profiling 資料，本庫只提供量測）。

## 18. 廣義分配律與連帶相信（`bp/`）

### 18.1 定理 F（GDL：局部化邊緣化）

若 ⊕ 對 ⊗ 分配（即半環），且因子圖是**樹**，則

    ⊕_{x_1..x_n} ⊗_f f(scope(f))

可以由「每個因子 → 每個變數 → 每個因子」的兩趟訊息傳遞在
`Σ_f q^{|scope(f)|}` 時間內算出精確邊緣，而不是 q^n。

推導只有一步：分配律允許把「與 x 無關的因子」提到 ⊕_x 外面。
重複使用就是可變消去（variable elimination）；在樹上，消去順序不影響結果且每個因子只被消去一次。

**同一段程式，兩種語義**（`bp/factor.mbt`）：

| 半環 | ⊕ / ⊗ | 演算法 | 得到什麼 |
|---|---|---|---|
| `Prob` | + / × | sum-product | 邊緣機率 |
| `TropMax` | max / + | max-product（取對數 = Viterbi） | MAP 指派 |

### 18.2 實測：樹上精確、有環近似

運算次數（⊕/⊗ 的實際呼叫次數，不是 Big-O），暴力 = q^n：

| n | 暴力 | 訊息傳遞 | 比值 |
|---|---|---|---|
| 4 | 48 | 396 | **0.12×（更差）** |
| 8 | 1792 | 1948 | 0.92× |
| 12 | 45 056 | 4652 | 9.69× |
| 16 | 983 040 | 8508 | **115.54×** |

**n=4 時 BP 比暴力更慢**，這個數字必須印出來：訊息傳遞有固定的啟動成本
（每條邊兩趟、每趟要建訊息張量），在小圖上完全划不來。**實測交叉點是 n = 9**：
n = 4…8 全部輸（n=4 時 396 vs 48 次乘法），n = 9 起轉正（1.63×），n = 16 時 115.54×（報告 §19a）。
任何「BP 總是更快」的宣稱都是沒量過的宣稱。

正確性：樹上邊緣與 q^n 暴力法相差 ≤ 5.3e-15（浮點捨入級別）。

有環的情形：三角形圖上 `is_tree = false`，BP 與精確邊緣的最大誤差 **0.008341427**。
測試把這個誤差**兩邊都夾住**：`> 1e-9`（斷言它確實不是精確的）且 `< 0.5`（斷言它沒有完全亂掉）。
這是「誠實的近似」在程式裡的寫法——既不假裝精確，也不放棄可用的下界。

### 18.3 為什麼不能對有環圖期待精確

已知結果（arxiv 1409.7410 等）：在一般交換半環上做精確推論是 NP-hard 的，
其特例即 #P-hard 的計數問題（`Counting` 半環上的邊緣化 = 數模型個數）。
所以「有環 ⇒ 用 BP 得到近似」不是實作偷懶，而是**問題本身的複雜度**：
精確解需要 junction tree（樹寬指數）或 cutset conditioning（迴圈切割，指數於迴圈數）。

本庫的立場寫進 API：`is_tree` 是一個回傳值，不是註解。呼叫端可以據此決定要不要相信數字。

### 18.4 邊界

- 只實作離散變數、有限基數、二元/多元因子；沒有連續變數、沒有高斯 BP。
- 沒有實作 junction tree、GBP（廣義 BP）、樹重加權（tree-reweighted）等改進。
- 沒有收斂保證：有環時用固定迭代次數 + 殘差回報，不收斂也會回傳最後一次的結果與殘差。

## 19. 已知限制

- 稀疏 Kleene 消去的常數偏大（每次更新重建列）⇒ 可測範圍內不如稠密 FW（§10.3）。
- 熱帶權重分兩種：`Trop`（Int，±2³⁰ 飽和，精確代數）與 `TropF`（Double，僅 ULP 內封閉）。
- `Trop` 的負環在 `star_checked` 回報錯誤；`csr_closure` / `csr_sssp` 以 `has_negative` 旗標回報。
- 分塊模型用 fill=3/4、磚數 2/3；沒有線上 auto-tuning，也沒有量到 NUMA。
- 位元平行閉包受 `n²/64` 記憶體限制（n=20000 約 50 MB）。
- **沒有 CPU 平行**：`par/` 目前只有單執行緒後端；真正的執行緒後端需要語言層支援。
- **平台擴充的隔離方式**：async 後端在 `par_host/`，以 `options(supported_targets: "native")` 宣告；
  其他 target 跳過整個套件，因此不會留下「編譯了但沒人用」的 import。若未來 `moon.pkg`
  支援按 target 條件化的 import（或 `#cfg` 在 import 前生效），可以把兩者合回一個套件。
- 限流器需要外部單調時鐘；本庫不擁有執行緒或計時器。
- **熱帶幾何只做到 2 個變數**：細分是 O(m⁴) 的三元組枚舉 + 全點檢查（實測有效斜率約 2.5），m 只到幾十；
  沒有增量凸包、沒有更高維、沒有 stable intersection 與交點重數。
- **熱帶根的輸入是整係數 `Int32` 多項式**；真正的熱帶多項式允許有理係數權重，
  本庫限定整數是為了讓下凸包的比較完全精確（有理可以通分後放大，但那會改變溢出行為）。
- **`nf/` 的判定能力有限**：Kleene 代數等式（正則語言）與自由冪等半環等式（有限語言）；
  交換半環、ℕ 半環的等式理論不在此列。最小化用 Moore O(n²·|Σ|)，不是 Hopcroft。
- **範疇化只做「集合值」**：見證是集合（基數）；沒有做真正的 2-範疇、也沒有做
  鏈複形／同調層級的範疇化（那需要商掉同構，超出本庫的資料結構能力）。
- **Maslov 解量化不是等式**：h→0 在浮點上不可達；`h < 1/709` 時 `e^(−x/h)` 就下溢，
  本庫給的是誤差曲線與下溢邊界，而不是「熱帶 = 極限」的實作。
- **`Prob` 沒有 `StarSemiring`**：機率星只在譜半徑 < 1 收斂，因此走 `closure_series` +
  `is_small` 旗標，收斂性是可檢查的回傳值而不是假設。
- **BP 只在樹上精確**：有環時誤差實測 8.3e-3（三角形圖），且一般半環上的精確推論是 NP-hard；
  本庫不提供 junction tree / GBP / tree-reweighting。
- 以上每一條在 `REPORT.md` §19 都有一個**現場量出來的數字**（交叉點 n=9、下溢邊界 h≈0.99、
  細分斜率 2.5、可信度價格 132× 與 2.13×、截斷級數 1022/1600 格錯）；限制不是形容詞，是可重跑的實驗。
- **演算法仲裁不保證正確**：只保證「這些候選在同一個輸入上一致」；共同的建模錯誤無法被發現，
  而且價格由最慢的候選決定（實測 118×）。
